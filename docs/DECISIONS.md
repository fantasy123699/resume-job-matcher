# 技术决策记录

| 编号 | 决策 | 结论 | 原因 |
| --- | --- | --- | --- |
| ADR-001 | 项目结构 | 单仓库，Web/API/Worker 三进程 | 个人维护成本低，同时保留清晰运行边界 |
| ADR-002 | 后端 | FastAPI + Pydantic | 文档处理、模型调用和 Agent 生态更适合 Python |
| ADR-003 | 持久化 | PostgreSQL 单一基础设施起步 | 业务数据、任务与检查点可统一持久化，避免提前引入队列和缓存 |
| ADR-004 | 开源 | Apache-2.0；前期只接收 Issue | 便于采用，同时在架构快速演进时保持版权边界清晰 |
| ADR-005 | 数据保留 | 导出 24 小时、审计 180 天、活跃删除 7 天、备份最长 35 天 | 在隐私、可追溯和单人运维成本之间平衡 |
| ADR-006 | Agent 边界 | 用户审批、无自动投递、Connector 默认关闭 | 防捏造、避免未授权访问和高风险对外行动 |
| ADR-007 | 首版界面基线 | “履历校准台”桌面优先工作台 | 将确认事实、JD 证据与逐项审批置于同一决策上下文，避免用不可解释的单一匹配分驱动用户操作 |
| ADR-008 | 邮箱发信 | QQ 邮箱 SMTP | 个人项目开发期零额外服务费；生产通过授权码发信，后续增长后可替换为事务邮件服务 |
